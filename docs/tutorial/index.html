PrintArtZ — Project Training Guide

A hands-on "learn a real full-stack project" course. Understand how PrintArtZ is built, then study each technology in an interview Q&A format — from basics to advanced — so you could walk into a full-stack interview and explain it all.

Big picture: a website has two halves — the frontend (what you see in the browser) and the backend (code on a server that talks to databases and other services). PrintArtZ keeps both in one codebase (Next.js) and calls out to specialist services (a database, an AI image generator, a payment company…).

How to use this guide

Start with How PrintArtZ works to see the moving parts, then open a Study topic. Each topic is a set of interview-style questions with answers and real code — click a question to expand it.

🎯 Goal: after finishing the topics you should be comfortable with TypeScript, React, Next.js, PostgreSQL, ORMs, CI/CD, servers/hosting and AI app concepts — the exact stack this project uses.

🔧 Service setup — every account, key & config

The exact steps used to register and wire up every external service in PrintArtZ. Follow these to recreate the whole stack from scratch. Secret values live in .env.local (and a private credentials note) — this page lists the where and how, not the secrets themselves.

Env var reference (values are in .env.local): DATABASE_URL, DIRECT_URL (Supabase) · OPENAI_API_KEY, AI_TEXT_MODEL=gpt-4o-mini, AI_IMAGE_MODEL=gpt-image-1, AI_IMAGE_QUALITY=medium (OpenAI) · AUTH_SECRET, NEXTAUTH_URL, AUTH_URL, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET (auth) · EMAIL_PROVIDER_API_KEY, EMAIL_FROM (Resend) · REDIS_URL (Upstash, unused yet) · RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, RAZORPAY_WEBHOOK_SECRET · NEXT_PUBLIC_APP_URL, NODE_ENV, NODE_VERSION=22.14.0.

URL: github.com/Yuushann/printartz (private). Remote uses SSH alias git@github.com-personal:Yuushann/printartz.git.

  1. Create a GitHub account; create a repo printartz.
  2. Add an SSH key; because this machine has multiple GitHub identities, an SSH host alias github.com-personal is configured in ~/.ssh/config pointing to the personal key.
  3. Branches: main (holds the private credentials note; otherwise stable), develop (integration + what Render deploys), feature/first_build (frozen first-live snapshot, tag first-build-live), second_build (active work). Flow: work on second_build → merge to develop → Render auto-deploys.

URL: supabase.com · Dashboard → your project.

  1. Sign up → New project. Region: Mumbai (ap-south-1). Pick a strong DB password (store it). Free tier (t3.nano).
  2. Connect modal → copy two connection strings into .env.local:
    • DATABASE_URL = Transaction pooler (port 6543, has ?pgbouncer=true).
    • DIRECT_URL = Session pooler (port 5432).
  3. Apply the schema: pnpm db:push (from repo root; loads .env.local). Inspect data in Table Editor or pnpm db:studio.

Gotchas: Free tier auto-pauses after ~7 days idle — resume in the dashboard. After a pause the pooler host can migrate (aws-0-… → aws-1-…); if connections fail, re-copy the strings from the Connect modal. On Windows/ARM64 we use Prisma's engine-free client (provider="prisma-client", engineType="client") + @prisma/adapter-pg because the classic Rust query engine has no arm64 build.

URL: platform.openai.com.

  1. Create an account + a project; add billing.
  2. API keys → create a project key (sk-proj-…) → OPENAI_API_KEY.
  3. Set models in .env.local: AI_TEXT_MODEL=gpt-4o-mini, AI_IMAGE_MODEL=gpt-image-1, AI_IMAGE_QUALITY=medium (low ≈ $0.01 / medium ≈ $0.04 / high ≈ $0.17 per image).
  4. Settings → Limits → set a monthly hard cap (we use $10/mo, alerts at $8/$10).

Gotcha: this account has NO DALL·E access — image models are gpt-image-1 / gpt-image-1-mini. Transparent die-cut art needs quality ≥ medium + a "die-cut sticker, isolated on transparent background" prompt.

URL: console.cloud.google.com.

  1. Create a project (printartz).
  2. APIs & Services → OAuth consent screen: External. Add your email as a Test user (or Publish to allow everyone).
  3. Credentials → Create credentials → OAuth client ID → Web application. Add:
    • Authorized JavaScript origins: http://localhost:3000 and https://printartz.co.in.
    • Authorized redirect URIs: http://localhost:3000/api/auth/callback/google and https://printartz.co.in/api/auth/callback/google.
  4. Copy Client ID/Secret → GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET. Generate AUTH_SECRET (openssl rand -base64 32). Set NEXTAUTH_URL + AUTH_URL to the site URL.

Note: we use Auth.js v5 with JWT sessions (required so email+password Credentials works alongside Google). The User model needs emailVerified DateTime? for the Prisma adapter.

URL: dcc.godaddy.com → Domain → DNS.

  1. Registered printartz.co.in (3-year term). Complete the NIXI/.in identity (KYC) validation email.
  2. DNS records for Render hosting (edit the existing defaults, don't duplicate):
    • A · Name @ · Value 216.24.57.1 (Render's apex IP).
    • CNAME · Name www · Value printartz-web.onrender.com.
  3. Leave NS, SOA, _domainconnect, _dmarc records alone. Resend's records were added automatically via GoDaddy "Domain Connect".

Gotcha: GoDaddy can't put a CNAME/ALIAS on the apex — the root must be an A record to Render's IP. Enable 2FA on the GoDaddy account.

URL: dashboard.render.com. (We chose Render over Vercel: it runs a persistent Node server with no request timeout, so synchronous image generation can't get killed.)

  1. New → Blueprint → connect the GitHub repo. Render reads render.yaml from the repo root.
  2. Set the deploy Branch to develop (Settings → Build & Deploy).
  3. Build command: pnpm install --frozen-lockfile && pnpm db:generate && pnpm build. Start: pnpm start. Health check path: /api/health. Plan: Free. Region: Singapore.
  4. Set all sync:false env vars in Environment (copy from .env.local): DB, auth, OpenAI, Google, Resend, URLs. Set NEXTAUTH_URL/AUTH_URL/NEXT_PUBLIC_APP_URL = https://printartz.co.in.
  5. Settings → Custom Domains → add printartz.co.in + www; then add the GoDaddy DNS records above; Render auto-issues SSL.

Gotchas: do NOT run corepack enable (read-only /usr/bin → EROFS); Render provides pnpm natively. Pin NODE_VERSION=22.14.0 (pnpm needs ≥22.13). Run pnpm db:generate explicitly in the build (a cached install skips the postinstall). Free tier spins down after ~15 min idle (~30–60s cold start) — see UptimeRobot below.

URL: resend.com.

  1. Sign up (free tier: 3,000/mo, 100/day).
  2. Domains → Add Domain → printartz.co.in (region Tokyo, return-path send) → click Add domain.
  3. Choose Auto-configure → it connects to GoDaddy (Domain Connect) and adds the SPF/DKIM/MX records automatically → Verify → wait for Verified ✅.
  4. API Keys → Create (sending access) → EMAIL_PROVIDER_API_KEY (re_…). Set EMAIL_FROM="PrintArtZ <no-reply@printartz.co.in>" (must be on the verified domain).

How it's used: on email+password signup we create a token, email a /verify?token=… link (built from the request host so it points at the real domain), and block generation until verified. Google logins are auto-verified. If EMAIL_PROVIDER_API_KEY is unset, verification is skipped (dev).

URL: console.upstash.com.

  1. Create a Redis database: Regional, Mumbai (ap-south-1), eviction OFF (required for BullMQ), TLS on.
  2. Copy the connection string into REDIS_URL using the rediss:// scheme (double-s = TLS).

Why: reserved for a future BullMQ background worker to run long image jobs off the request. Currently unused — generation is synchronous, and Render has no request timeout, so it isn't needed yet. Can stay idle on the free tier until we build the worker.

URL: dashboard.razorpay.com.

  1. Sign up → stay in Test mode. Settings → API Keys → Generate → RAZORPAY_KEY_ID (rzp_test_…) + RAZORPAY_KEY_SECRET.
  2. Webhooks (later, once a public URL exists): create a webhook → set RAZORPAY_WEBHOOK_SECRET.
  3. For LIVE payments: complete business/bank/PAN KYC to get live keys.

Status: test keys stored; the payment flow itself is not built yet (next task).

URL: uptimerobot.com.

  1. Sign up (free). + New monitor → Type HTTP(s), Name PrintArtZ, URL https://printartz.co.in/api/health, interval 5 minutes → Create.

Why: Render's free service sleeps after ~15 min idle; a 5-minute ping to the lightweight /api/health keeps it awake (and gives free uptime alerts). Uses ~730 of 750 free instance-hours/mo — fits one service.
